## 3. Regenerating Drew's profile: what the script does not cover

The script (`scripts/regenerate-combined-profile.ts`) is sound. It already dry-runs by default,
refuses to write when only the deterministic fallback was produced (`!res.generated` → exit 2),
diffs the old vs new AI-era cells, and documents the stale-tab caveat. Three things it does not handle:

1. **No backup of the old narrative.** Step 5 upserts straight over `reports(kind='combined')`.
   The old copy is read into `rep.data.narrative` and used only for the diff print, then discarded.
   **Dump it to a local JSON file before `--write`.** There is no undo and this is a real person's report.

2. **Drew is a stakeholder, not a test user.** `drewcline168@gmail.com`, provisioned as an `admin` on 8/12.
   He raised the original complaint and will open this and compare it against what he saw.
   **Show Will the dry-run diff before running `--write`.**

3. **Regeneration re-rolls the entire narrative, not just the AI-Era headings.**
   Scores are deterministic so those hold, but every prose field will come back as different text.
   Drew asked only for "the AI Readiness headings." He may not expect the whole report to read differently.
   That is Will's call to make and Will's message to send, not the agent's.

Also confirm `reportModelLabel()` in the dry-run output matches what production uses. If `.env.local`
points at a different provider than prod, the regenerated report will not match what the live app produces.

### Sync will not clobber the write (verified)
`AccountSync.tsx` runs `pullToLocal` **before** setting `ready.current = true`, and `pushToCloud` only
fires on a `STORE_EVENT` after that flag is set. So on Drew's next login the cloud row wins and overwrites
his localStorage. The regeneration survives.

**The one exception:** if Drew has a browser tab already open and hydrated when the write lands, a
`STORE_EVENT` in that tab pushes his stale localStorage copy back over the new row. The upsert has no
timestamp guard, so last writer wins. Tell Drew to fully close the app and reopen after the write.
